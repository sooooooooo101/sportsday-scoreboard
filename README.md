# 体育祭 得点ボード

学校の体育祭（青組 vs 白組）向けの、リアルタイム得点ボードです。

- **表示画面**：誰でもスマホで開ける。得点が入ると 1 秒ほどで全員の画面に反映される
- **管理画面**：得点係だけが合言葉で入る。試合ごとに青と白の点数を入力する

実際の体育祭（競技 5 種目・1 日開催）で使うために、6 日で作りました。

## 主な機能

**表示画面**
- 青組と白組の合計点を大きく表示する（スマホを縦に持つと上下、横に持つと左右に並ぶ）
- 点が入ると数字がなめらかに増え、点が入った側が一瞬光る
- 競技ごとの内訳は、見る人が自分で開け閉めできる（最初は閉じている）
- 最後の競技は結果を「?」で隠しておき、閉会式で数字が増えていく演出とともに発表できる
- 通信が切れたら「再接続中」と出して、つながったら自動で最新の点数に戻る

**管理画面**
- 競技 → 試合 → ＋/− ボタン、数字の直接入力、よく使う点数のボタン（押すと今の点数に足す）
- 保存すると中央に「✓ 青組 40点 保存しました」と出る。5 秒間は「取り消す」が押せる
- 玉入れ用の途中計算：入った玉（＋）とマイナス玉（−）を数えて、「点数決定」で差し引きを保存する。ボーナスラウンドは「1 球目 +3・2 球目 +5・3 球目 +10」で計算する。数えている途中の数はそのスマホに残る（3 時間で自動的に消える）
- 電波が悪いときは入力をスマホにためておき、つながったら自動で送る
- 競技名・試合数・満点・よく使う点数は、当日でも設定画面から変えられる

## 仕組み

```
得点係のスマホ（管理画面）──書き込み──▶ Firestore ──リアルタイム購読──▶ 観客のスマホ（表示画面）
        │                                   ▲
        └── 得点係アカウントでログイン ──────┘  セキュリティルールで「得点係だけが書き込める」と決める
```

- `competitions/{A..E}`：競技ごとの設定と、試合ごとの点数 `scores: { "1": { blue, white }, ... }`
- `settings/app`：満点の数え方、結果を隠す設定
- `log/{id}`：点数と設定の変更の記録（時刻はサーバー時刻）

## セキュリティの考え方

点数を守る仕組みは、画面ではなく **Firestore のセキュリティルール**（[firestore.rules](firestore.rules)）に置いています。開発者ツールでアプリの通信を直接いじっても、ルールに反する書き込みはサーバーが拒否します。

- 書き込めるのは得点係アカウント（UID で指定）だけ。それ以外はすべて拒否する
- 1 競技の合計が満点を超える書き込みは拒否する。書き込んだあとのデータで判定するので、2 人が同時に入力しても抜け道がない
- 点数が入っている試合が消えるような「試合数の削減」は拒否する。今の合計より低い満点への変更も拒否する
- 結果を隠している競技は、未ログインでは読めない。画面に表示しないだけでなく、データそのものを渡さない
- 変更の記録は追加だけで、書き換えも削除もできない

そのほかの対策：
- 管理画面は推測しやすい `/admin` には置かず、ランダムな文字列のパスに置く（デプロイ時に `.env.local` の `ADMIN_PATH` から決まる）
- 得点係の UID は、リポジトリの `firestore.rules` には書かない。デプロイするときに差し込む（[scripts/build-rules.ts](scripts/build-rules.ts)）
- 秘密情報（Firebase の設定、UID、管理画面のパス）は、すべて git の管理外の `.env.local` に置く

## ローカルで動かす

必要なもの：Node 22 以上、Java 21（Firestore エミュレーターに必要）

```bash
npm install
npx firebase emulators:start --only firestore,auth --project demo-sportsday
```

別のターミナルで：

```bash
node scripts/dev-setup.mjs --seed   # エミュレーターに得点係ユーザーとサンプルデータを作る
npm run dev                         # 表示画面 http://localhost:5173/ 、管理画面 http://localhost:5173/admin/
```

開発用の合言葉は `scripts/dev-setup.mjs` の `DEV_PASSCODE` です。`node scripts/dev-poke.mjs score C 1 blue 40`（`hide` / `reveal` も可）で、エミュレーターのデータを直接変えて表示を確かめられます。

## テスト

```bash
npm test             # 単体テスト・画面のテスト（エミュレーター不要）
npm run test:emu     # セキュリティルールとデータ層のテスト（Java が必要）
npm run typecheck
npm run build
```

`test:emu` では、得点係以外の書き込み、同時入力、満点、隠した競技の閲覧、オフラインでの入力などを、実際のエミュレーターに対して確かめています。

## デプロイ

1. Firebase プロジェクトを作る
   - Authentication で「メール / パスワード」を有効にし、「作成（登録）を許可」はオフにする
   - 得点係ユーザーを 1 人だけ追加する（パスワード＝合言葉、12 文字以上）
   - Firestore を作る
2. `.env.example` をコピーして `.env.local` を作り、Firebase の設定値、`VITE_SCORER_EMAIL`、`SCORER_UID`、`ADMIN_PATH`（`openssl rand -hex 16`）を入れる
3. 公開する

   ```bash
   npx firebase login
   npx firebase use <プロジェクトID>
   npm run deploy
   ```

`npm run deploy` は、UID を差し込んだルールを作り、ビルドし、管理画面を秘密のパスへ移してから公開します。UID やパスが空・不正なら、公開せずに止まります。

### 運用メモ

- **合言葉が漏れたとき**：Firebase コンソールで得点係ユーザーのパスワードを変える。すでにログインしている端末は、最長 1 時間ほどログインしたままになる場合がある
- **管理画面の URL が漏れたとき**：`ADMIN_PATH` を変えて `npm run deploy`
- **無料プラン（Spark）の読み取り上限**：点数を 1 回入れるたびに、表示画面を開いている人数分の読み取りが発生する（無料プランは 1 日 5 万回まで）。観客が多いときは Blaze プランに切り替えて、予算アラートを設定しておく

## 競技のルール

各競技の点数の付け方は [docs/reference/競技部門A-E_抽出.md](docs/reference/競技部門A-E_抽出.md) にまとめています。満点は 1 競技につき青と白の合計で 100 点です。ただし玉入れだけは 1 チーム最大 98 点（ラウンド 1・2 は 80 点まで、ボーナスは 18 点まで）なので、合計が 100 点を超えてもよい設定にしています。
