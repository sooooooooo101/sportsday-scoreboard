体育祭 得点ボード 来年の手順書（AIなし版）

対象：Claude Code や Codex などのAIを使えない担当者
この手順書は、上から順に実行すれば進められるように書いています。秘密の値は書いていません。


0. まず決めること：どちらのコースにするか

コースA：作り直さない（いちばん簡単。プログラミング不要）
　・去年作ったサイトは、Firebase に置かれたまま動き続けます。何もしなくても消えません。
　・やること：Firebase のオーナー権限を受け取る → 管理画面で点数を0に戻す → 設定で競技の内容を変える
　・向いているのは、合言葉と管理画面のURLを去年と同じにしてよい場合です。
　・注意：去年の得点係が合言葉と管理画面のURLを知っています。漏れても困らないか、事前に考えてください。

コースB：作り直す（合言葉・管理画面のURLを新しくしたい／競技のルールそのものを変えたい）
　・パソコンでコマンドを打つ作業があります。ただし、この手順書の通りにコピーして貼り付ければ進められます。
　・競技のルールをプログラムごと変える場合（玉入れをなくす、満点の考え方を変える、など）は、プログラムを書き換える必要があります。そのときはプログラミングができる人に頼んでください（ルールの確認は10章に書いています）。


1. 最初にやること（2026年の担当者が、引き継ぎの前にやっておく）

何も起きていない今のうちに、次の4つを済ませておくと、来年ほとんど困りません。

（1）Firebase プロジェクトのオーナーを2人にする
　・Firebase コンソール → 歯車 → 「ユーザーと権限」→「メンバーを追加」→ 来年の担当者のGoogleアカウントを「オーナー」で追加
　・作成者のGoogleアカウントが使えなくなると、プロジェクトに入れなくなります。これが最大のリスクです。
（2）GitHub のリポジトリの管理者を2人にする
　・このリポジトリの Settings → Collaborators から追加します。
　・または、リポジトリをクローンして自分のアカウントにコピー（Fork）してもらいます。
（3）.env.local の内容をパスワード管理アプリ（1Password など）に保存する
　・場所：作成者のMacの、プロジェクトフォルダの中の .env.local
　・Macが壊れるとこのファイルが消えます。
　・実は、消えても多くは再取得できます。
　　　Firebaseの設定値（VITE_FIREBASE_〜）：Firebase コンソール → プロジェクトの設定 → マイアプリ
　　　得点係のUID：Authentication → ユーザー
　　　合言葉とADMIN_PATH：再取得はできません。新しく作り直します（コースB）。
（4）合言葉を、パスワード管理アプリに保存する（コースAを選ぶ場合は必須）

保管場所は、来年の担当者に直接伝えてください。メールやチャットで秘密の値そのものを送らないでください。


2. コースA：作り直さない場合の手順

（1）Firebase コンソール（https://console.firebase.google.com/）に、オーナーに追加されたGoogleアカウントでログインし、去年使っていたプロジェクトを開く
（2）管理画面を開く
　・URLは https://<プロジェクトID>.web.app/<ADMIN_PATH>/ です。ADMIN_PATH は、保存してある値を使います。
　・合言葉を入れてログインします。
（3）去年の点数を0に戻す
　・各競技・各試合の数字をタップして「0」を入れます。
　・結果を隠していたら、「設定」→「発表する」で元に戻します。
（4）競技の内容を変える
　・「設定」で、競技名・実施順・試合数・満点・よく使う点数を変えられます。
　・変えたら「競技の設定を保存」を押します。
（5）表示画面（https://<プロジェクトID>.web.app/）で、反映されたことを確かめる
（6）リハーサルをして、終わったら点数を0に戻す（操作マニュアルの10章）

コースAでできないこと：競技の数を5つ以外にする、玉入れ以外の競技にも玉入れの途中計算を付ける、など。これらはコースBでプログラムを書き換える必要があります。


3. コースB：作り直す場合の手順

3-1. パソコンの準備（初回だけ）

（1）Node.js（バージョン24以上）を入れる
　・https://nodejs.org/ から「LTS」ではなく、24以上のバージョンを入れてください。
　・確認：ターミナルを開いて  node -v  と打ち、v24 以上と出ればOK。
　・古いバージョンだと、npm run deploy の途中で止まります。
（2）Git を入れる（Macは、ターミナルで git と打つと案内が出ます）
（3）Firebase のコマンドは、後の手順で自動的に入ります

※ターミナルの開き方（Mac）：Command + スペースキーで「ターミナル」と入力して Enter

3-2. プログラムを手に入れる

ターミナルで、次を1行ずつ貼り付けて Enter を押します。

  git clone <このリポジトリのURL>
  cd sportsday-scoreboard
  npm install

3-3. 得点係アカウントを新しく作る

（1）Firebase コンソール → Authentication → ユーザー → 「ユーザーを追加」
　・メールアドレス：推測できない文字列にします（例：ランダムな英数字 @example.invalid）。実在するアドレスでなくても大丈夫です。
　・パスワード：16文字以上のランダムな文字列。これが新しい合言葉です。パスワード管理アプリで作ると楽です。
（2）追加したユーザーの「ユーザーUID」をコピーしておく
（3）Authentication → 設定 で、「作成（登録）を許可」がオフ、「メール列挙保護」がオンになっていることを確かめる
（4）新しい合言葉でログインできることを確かめてから、去年のユーザーを削除する

3-4. 設定ファイル .env.local を作る

（1）ターミナルで次を実行して、ひな形をコピーします。

  cp .env.example .env.local

（2）.env.local をテキストエディタで開き、各項目を埋めます。

  VITE_FIREBASE_API_KEY、VITE_FIREBASE_AUTH_DOMAIN、VITE_FIREBASE_PROJECT_ID、VITE_FIREBASE_APP_ID
　　→ Firebase コンソール → プロジェクトの設定 → 全般 → マイアプリ → ウェブアプリの設定
  VITE_SCORER_EMAIL
　　→ 3-3で作ったメールアドレス
  SCORER_UID
　　→ 3-3でコピーしたUID
  ADMIN_PATH
　　→ ターミナルで  openssl rand -hex 16  を実行して出た32文字
  VITE_USE_EMULATOR
　　→ false のままにする

（3）.env.local はGitに入れないファイルです。他人に渡さないでください。パスワード管理アプリに保存してください。

3-5. 公開する

  npx firebase login
  npx firebase use <プロジェクトID>
  npm run deploy

・<プロジェクトID> は、Firebase コンソールの「プロジェクトの設定」に出ているIDです（作成者の引き継ぎメモにも書いています）。
・最初の firebase login で、ブラウザが開きます。オーナー権限のGoogleアカウントでログインしてください。
・必ず npm run deploy を使ってください。firebase deploy を直接打つと、管理画面が /admin/ という推測しやすい場所に公開されてしまいます。
・成功すると、最後に Hosting URL が表示されます。

新しくFirebaseプロジェクトを作る場合は、先に Firestore（東京リージョン）と Hosting を作り、npx firebase use の後ろをそのプロジェクトIDに変えます。詳しくはリポジトリの README.md の「デプロイ」の章にあります。

3-6. 動作を確かめる

（1）表示画面を開く：https://<プロジェクトID>.web.app/
（2）管理画面を開く：https://<プロジェクトID>.web.app/<ADMIN_PATH>/ → 新しい合言葉でログイン
（3）点数を入れて、表示画面に数秒以内に反映されることを確かめる
（4）「設定」で「隠す」→ 別のスマホで表示画面を見て「?」になることを確かめる → 「発表する」で戻す
（5）リハーサルが終わったら、点数をすべて0に戻す。隠していたら必ず「発表する」で戻す

3-7. 去年のデータを消したいとき

Firebase コンソール → Firestore Database で、competitions の各ドキュメントの scores を空にする方法もありますが、間違えやすいので、管理画面から0を入れる方法をおすすめします。


4. うまくいかないとき（よくある原因）

・npm run deploy が「SCORER_UID が正しくありません」で止まる
　→ .env.local の SCORER_UID が空、または別の文字が混ざっています。UIDを入れ直してください。
・npm run deploy が「ADMIN_PATH〜」で止まる
　→ ADMIN_PATH が小文字の英数字24〜64文字になっていません。openssl rand -hex 16 で作り直してください。
・npm run deploy の途中で node のエラーが出る
　→ Node のバージョンが古いです。node -v を確認し、24以上を入れ直してください。
・firebase login や deploy で権限エラーが出る
　→ ログインしたGoogleアカウントがオーナー権限を持っていません。1章（1）を確認してください。
・管理画面にログインしても「読み込み中」のまま
　→ 5秒待って「ログインし直す」を押す。それでも直らないときは、.env.local の VITE_SCORER_EMAIL と、Firebase に登録したメールアドレスが同じか確かめて、もう一度 npm run deploy します。
・表示画面に「再接続中…」が出続ける
　→ ネットワークを確かめる。Firebase コンソールで Firestore が止まっていないか、無料枠（1日の読み取り5万回）を超えていないかを確かめる。
・どうしても分からない
　→ エラーメッセージをそのままコピーして、無料版のAI（ChatGPT、Claude、Gemini など）に貼って聞いてください。その際は .env.local の中身や合言葉を貼らないでください。


5. 費用

・Firebase は無料プラン（Spark）のまま使えます。2026年は費用ゼロでした。
・観客が多く、1日の読み取りが5万回を超えそうなときだけ、Blaze（従量課金）に切り替えます。切り替えるときは、Firebase コンソールで予算アラート（例：月500円）を必ず設定してください。
・AIの有料プラン（Claude Code、Codex など）は、この手順書の作業には要りません。


6. 本番の前日までのチェックリスト

□ オーナー権限を持っている人が2人以上いる
□ 管理画面のURLと合言葉を、パスワード管理アプリに保存した
□ 合言葉と管理画面のURLを、得点係に直接伝えた（メッセージで送られたリンクは開かないよう伝えた）
□ リハーサルをして、点数をすべて0に戻した
□ 結果を隠した場合は「発表する」で元に戻した（リハーサルで隠したまま本番を迎えないこと）
□ 得点係のスマホで、開会式の前にログインしておいた


7. 去年の経験から（失敗しやすいところ）

・リハーサルで「隠す」を押したまま、元に戻し忘れた。
・得点係アカウントを作り直したあと、古いアカウントでログインしたままのスマホが「読み込み中」で止まった。
・合言葉を使い回すと、前の担当者が知っている状態になる。

・競技の一覧と初期値：src/shared/seed.ts
・玉入れ専用のルール：src/shared/tamaire.ts（競技ID「B」に結びついています）
